# MiniSense — A Survey Analysis Agent

A small, runnable AI system that answers business questions about survey feedback using a
two-level agent architecture (LangGraph) and a document-grounded RAG pipeline (LangChain + FAISS).

## What's here

- `MiniSense_Agent.ipynb` — the full implementation: data generation, RAG pipeline, all four
  sub-agents, the LangGraph orchestrator, and the evaluation checkpoint (Parts 1 & 2).
- `README.md` — this file, including the fine-tuning design write-up (Part 3).
- `requirements.txt` — dependencies.
- `survey_data.json`, `faq.txt` — generated by the notebook on first run.

## Running it

```bash
pip install -r requirements.txt
jupyter notebook MiniSense_Agent.ipynb
```

Run all cells top to bottom. No API key is required — the notebook runs fully offline by
default (see "Design decisions" below). To use a real LLM for the final narrative step, set
`OPENAI_API_KEY` or `ANTHROPIC_API_KEY` as an environment variable before starting Jupyter.

## Architecture

```
User question
     │
     ▼
Orchestrator (planner)  ── breaks question into TaskSpecs, decides routing
     │
     ├─► DataAgent / ComparisonAgent   (exact metrics from survey JSON; calls compute_csat() as a tool)
     ├─► RAGAgent                       (retrieves relevant FAQ chunks from FAISS)
     │
     ▼
SummaryAgent  ── synthesizes structured results into one narrative paragraph
```

Built as a `StateGraph` in LangGraph: `planner → [comparison_agent | data_agent] → [rag_agent] →
summary_agent → END`. Every sub-agent receives a structured `TaskSpec` and returns a structured
dataclass, per the assignment's requirements — no raw text passed between agents.

## Design decisions (scope trade-offs)

- **Embeddings: TF-IDF instead of sentence-transformers/OpenAI.** Real sentence embeddings need
  a model download or an API key, which isn't guaranteed to be available in every environment.
  TF-IDF needs neither and is instant on a 13-chunk document. The notebook documents exactly
  where this falls short in the evaluation section — a real embedding model is the natural next
  step before any production use.
- **Planner: rule-based, not LLM-based.** The question-routing logic is small and deterministic
  enough that a keyword rule set is simpler and cheaper than an LLM call, with no accuracy loss
  at this scope. An LLM planner is the natural upgrade once the rule set outgrows a handful of
  keywords.
- **SummaryAgent: LLM with a template fallback.** Uses a real LLM when an API key is present,
  and a deterministic template otherwise, so the whole system is runnable and reproducible with
  zero setup.

## Evaluation checkpoint

Three sample questions are run in the notebook, showing retrieved chunks and the final answer
for each. Findings:

- **Worked well:** questions using FAQ-distinctive terms (e.g. "CSAT target") retrieved the
  correct chunk cleanly.
- **Fell short:** a question about "wait time" pulled unrelated chunks, because TF-IDF is
  bag-of-words — a query and its answer sharing few exact words (e.g. "wait time" vs. "how long
  we waited") isn't matched, and common words in the query (e.g. "customer", "feedback") won
  out over the one relevant keyword. A real sentence-embedding model would likely fix this.

## Part 3 — Fine-Tuning Design (300–500 words)

**Scenario:** omniSense needs to classify 10,000 free-text survey responses/day into 8
sentiment+topic categories. GPT-4o is accurate but too costly to run at that volume every day.

**1. Data strategy.** I'd use the current LLM/GPT-4o pipeline to *label* a sample of real (or
realistic synthetic) free-text responses across the 8 categories, stratified to avoid
collapsing into the two or three most common classes — survey text skews heavily positive, so
"Negative" categories need deliberate oversampling in training even though they're rarer in
production. I'd target roughly **1,500–3,000 labeled examples** (150–350 per class) as a
starting point for LoRA fine-tuning on a strong open base model — classification into a fixed
small label set needs far fewer examples than open-ended generation. I'd hold out ~15% as a
fixed test set that's never touched during iteration, plus a rolling weekly sample of new
production data for drift checks.

**2. Model & technique selection.** A compact open model in the 3B–8B range (e.g. Llama 3.1 8B
or Qwen2.5 7B) is a strong base — the task is classification, not open-ended reasoning, so a
large model is overkill. I'd use **QLoRA**: full fine-tuning is unnecessary and expensive for a
single classification head, and QLoRA's 4-bit quantization keeps training on a single GPU
feasible, which matters given that the whole point of this project is cutting cost versus a
frontier model.

**3. Training pipeline.** Hugging Face `Trainer` with `peft` for the LoRA adapters is the
simplest path at this scope — no need for Axolotl or LLaMA-Factory's extra features. I'd frame
it as classification over the 8 labels, train a few epochs with early stopping on a held-out
validation split, and log runs to a simple tracker (e.g. Weights & Biases) so they're
comparable.

**4. Evaluation.** Per-class precision/recall/F1 (not just overall accuracy — accuracy hides
underperformance on rare classes like "Negative - Wait Time"), plus a confusion matrix. I'd
promote the fine-tuned model to production only once it's within an agreed tolerance (e.g.
within 2-3 points of macro-F1) of GPT-4o on the held-out test set *and* on the most recent week
of real traffic — the two can diverge as customer language shifts over time.

**5. Serving.** Serve the LoRA adapter alongside the existing LLM service using a single
base-model deployment with multiple adapters loaded (e.g. via vLLM's multi-LoRA serving),
routed by request type, so other LLM-backed routes are untouched and the base model isn't
duplicated per adapter.

**6. Future-proofing.** Keep the labeling schema and prompt/label mapping in a versioned config
file, not hardcoded — so adding a 9th category or adapting to a different client's category set
requires only a config change and a fresh labeled batch, not a training-code change.
